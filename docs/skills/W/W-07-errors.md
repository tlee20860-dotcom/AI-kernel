# W-07 Web App 通用錯誤與防呆

最後更新：2026-10-31
用途：沉澱 Web App 開發過程中的通用錯誤與防範措施（含 SPA 動態渲染與資料清洗實戰經驗）

---

## 一、通用開發錯誤（交付前檢查）

> 以下為跨專案通用的開發與交付防呆，體系的 `R-00` 規則與此處互補。

| # | 類型 | 防止做法 |
|---|---|---|
| 1 | 估算前未掃描實際檔數 | 先全域掃描（grep） |
| 2 | 「統一」誤解為各檔都改 | 統一 = 邏輯集中一處 |
| 3 | 未檢查現有 API 複用 | 先找複用機會 |
| 4 | 未思考集中層強制 | 優先改集中層 |
| 5 | 動態值用快照 | 內部讀取狀態（AppState） |
| 6 | 動態注入未清空 | 先執行 `textContent = ''` |
| 7 | 全站結構改動未完整掃描 | 完整掃描後才動 |
| 8 | 自我引入 bug | 交付前全鏈路檢查 |
| 9 | 狀態字串硬編碼 | 全走 `status-registry` |
| 10 | 邊界值未特判 | 需針對 0、null、空字串做邊界處理 |

## 二、SPA 與動態渲染致命陷阱（實戰血淚）

| # | 錯誤現象 | 根本原因 | 正確解法 |
|---|---|---|---|
| 1 | 切換頁面後按鈕全死 | 使用 `addEventListener` 綁定在特定 DOM 上，路由切換重繪後監聽器失效 | 改用「全域事件委派」，綁定在 `document` 上，透過 `data-action` 辨識 |
| 2 | 圖示渲染報錯導致白屏 | 先呼叫 `createIcons()`，發生錯誤後中斷，導致後續綁定事件或渲染資料的程式碼被跳過 | 先綁定事件（或使用事件委派），最後才呼叫 `createIcons()` |
| 3 | 設定檔沒更新導致畫面全白 | 舊版資料庫 Schema 缺少新欄位，渲染時抓不到資料 | 加入 Fallback 防呆，若 `Schema` 為空則自動補上核心欄位（如 `id`, `status`） |
| 4 | 表格在手機端文字斷行變形 | 表頭未鎖定寬度，被瀏覽器強制擠壓 | 表頭加上 `whitespace-nowrap` 與 `min-w-[120px]`，外層加 `overflow-x-auto` |
| 5 | 彈窗底部按鈕在手機消失 | 彈窗內文過長，把按鈕擠出螢幕外，且無法滑動 | 重構為三層架構（Header / Body / Footer），按鈕放在 Footer 固定，Body 設 `overflow-y-auto` |
| 6 | 設定頁改了選項，前台沒更新 | 各頁面使用快取資料，未即時監聽資料庫變更 | 在 `main.js` 監聽 `settings`，變更時派發 `settings-updated` 事件，前台監聽並刷新 |
| 7 | 雙清單拖曳後序號錯亂 | 只更新了 DOM 結構，沒有重新渲染畫面 | 在 `dragend` 事件中，重新收集陣列並呼叫 `renderLists()` 重繪以更新序號 |
| 8 | 手機端無法拖曳排序 | 使用原生 `draggable="true"`，手機會判定為滑動頁面 | 引入 `SortableJS`，並設定 `forceFallback: true` |
| 9 | 自動同步讀取本機檔案報錯 | 使用者重新整理網頁導致授權失效 | 輪詢前檢查 `queryPermission`，失效時停止輪詢並提示重新綁定 |

## 三、Excel 匯入與資料清洗（防呆）

| # | 錯誤現象 | 根本原因 | 正確解法 |
|---|---|---|---|
| 1 | 匯入後多出「客戶查看中心」等垃圾資料 | Excel 底部帶有總計、星號備註，被當成資料列解析 | 解析時若遇到 A 欄（主鍵）為空，直接 `break` 中斷迴圈 |
| 2 | 日期顯示 `46300` | 讀取到 Excel 的日期序列號，未經轉換直接存入 | 加入日期轉換函式，若數值大於 20000 則轉為 `YYYY-MM-DD` |
| 3 | 重新匯入導致手動進度被重設 | 匯入時直接覆蓋了整筆資料 | 比對 ID，若已存在則只更新 Excel 欄位，保留 `status` 與 `dueDate` |
| 4 | 新工單沒有專屬製程路線 | 匯入時只給定預設狀態，未依產品類別套用對應模板 | 匯入時解析工單類別（如發票前兩碼），比對 `route_templates` 中的 `category`，找到對應模板並寫入 `route` |
| 5 | 匯入時狀態與區域不匹配 | 自訂區域設定了類別限制，但匯入時未考慮 | 匯入時必須將工單類別 (`category`) 與區域的 `categories` 比對，決定是否將該工單加入該區域。 |

## 四、Cloudflare Pages (CF Pages) 教條

| 教訓 | 說明 |
|---|---|
| Functions 路由 | 每個 URL 應對應獨立實體檔或統一 Catch-all |
| 不支援 shim | 用底線前綴（`_xxx.js`），避免跨檔 re-export |
| 靜態檔案 | 所有連結需帶 `.html` |
| _redirects | 不要對 `/` 加規則，避免無限迴圈 |
| 環境變數 | 走 handler `{ env }`，非 `process.env` |
| 移除 export | 刪除既有 export 會導致依賴模組崩潰，應改用 `export let` |

## 五、Page Engine 與 ES Module 教條

| 教訓 | 說明 |
|---|---|
| customMount | 必須支援，供複雜邏輯逃生 |
| onDataChange | 必須支援非同步資料流 |
| 依賴圖 | key 與事件觸發必須一致 |
| undefined | derived 計算需容忍初始 undefined |
| 動態值 | 必須內部讀取最新狀態，不可快照 |
| 動態注入 | 需先清空既有內容 |
| esc 函式 | 必須從統一 `lib/dom.js` 導入 |
| format 函式 | 必須從統一 `lib/format.js` 導入 |
| 檔案搬移 | 必須全域搜尋並替換舊路徑 |
| 無補丁 | 寧願整檔重寫，減少修補風險 |
| 權限狀態遺失 | 登入時必須將 `allowedAreas` 與 `allowedSales` 存入全域狀態，否則各頁面無法正確過濾資料。 |

## 七、交付前必查清單

| # | 檢查項目 |
|---|---|
| 1 | 已跑 5 問自檢（體系 R-00） |
| 2 | 已掃描實際檔數與受影響範圍 |
