## 一、新增頁面

| 步驟 | 動作 |
|---|---|
| 1 | 讀 W-03 + W-05 |
| 2 | 檢查專案架構是否可複用 |
| 3 | 寫 `js/pages/xxx.js`（Schema） |
| 4 | 寫 `xxx.html` |
| 5 | 更新側邊欄導覽設定（如 constants.js） |
| 6 | 更新 Service Worker 的 STATIC_ASSETS（見 W-04） |
| 7 | 更新專案對應的頁面區塊規格書 |
| 8 | 更新專案檔案清單與進度紀錄 |

---

## 二、部署後驗證

| 步驟 | 動作 |
|---|---|
| 1 | 訪問主要頁面 |
| 2 | 檢查 Console 是否有 Error |
| 3 | 切換連動元件（如年月） → 驗證連動 |
| 4 | 檢查 API 回應是否正常 |
| 5 | 手機 / 跨裝置測試 |

**通用驗證清單**：
- [ ] 登入 / 註冊流程正常
- [ ] 統計卡有數字
- [ ] 分頁 / 篩選器可運作
- [ ] 各 Modal 可正常開啟與關閉
- [ ] 表格與卡片視圖切換正常
- [ ] 空狀態顯示正確

---

## 三、緊急回滾

| 步驟 | 動作 |
|---|---|
| 1 | 至 GitHub 尋找上一個穩定的 commit |
| 2 | 執行 Revert 或強制將分支重置到該 commit |
| 3 | 等待部署平台（如 CF Pages）自動重部署 |
| 4 | 驗證線上版本是否恢復 |
| 5 | 分析事故原因後重做 |

**禁止**：手動修改線上檔案、強制 push 覆蓋歷史（除非極端情況）。
