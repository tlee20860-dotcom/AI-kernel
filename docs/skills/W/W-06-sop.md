## 一、新增頁面

| 步驟 | 動作 |
|---|---|
| 1 | 讀 W-03 + W-05 |
| 2 | 檢查專案架構是否可複用 |
| 3 | 寫 `js/pages/xxx.js`（Schema） |
| 4 | 寫 `xxx.html` |
| 5 | 更新側邊欄導覽設定（如 constants.js） |
| 6 | 更新 Service Worker 的 STATIC_ASSETS（見 W-04） |
| 7 | 更新專案對應的頁面區塊規格書 |
| 8 | 更新專案檔案清單與進度紀錄 |

## 二、部署後驗證

| 步驟 | 動作 |
|---|---|
| 1 | 訪問主要頁面 |
| 2 | 檢查 Console 是否有 Error |
| 3 | 切換連動元件（如年月） → 驗證連動 |
| 4 | 檢查 API 回應是否正常 |
| 5 | 手機 / 跨裝置測試 |

**通用驗證清單**：
- [ ] 登入 / 註冊流程正常
- [ ] 統計卡有數字
- [ ] 分頁 / 篩選器可運作
- [ ] 各 Modal 可正常開啟與關閉
- [ ] 表格與卡片視圖切換正常
- [ ] 空狀態顯示正確

---

## 三、緊急回滾

| 步驟 | 動作 |
|---|---|
| 1 | 至 GitHub 尋找上一個穩定的 commit |
| 2 | 執行 Revert 或強制將分支重置到該 commit |
| 3 | 等待部署平台（如 CF Pages）自動重部署 |
| 4 | 驗證線上版本是否恢復 |
| 5 | 分析事故原因後重做 |

**禁止**：手動修改線上檔案、強制 push 覆蓋歷史（除非極端情況）。

## 四、重寫與重構驗證

用途：證明重寫前後的行為一致，適用任何含計算邏輯、業務流程的 Web App 重寫。

**核心原則**：先凍結，再重寫；先驗證，再清舊。

| 項 | 編號前綴 | 產出物 | 依賴 |
|---|---|---|---|
| 公式凍結 | FZ | 凍結清單 | 舊檔 |
| 差分驗證 | DT | 測試紀錄 | FZ |
| 驗收清單 | AC | 勾選表 | 新版可跑 |
| 可回滾 | — | 目錄結構 | 全程 |

### 4.1 公式凍結（Formula Freeze）

| 項目 | 內容 |
|---|---|
| 目的 | 證明「業務計算未被重寫悄悄改變」 |
| 觸發 | 任何涉及計算邏輯的重構／重寫 |
| 適用 | 財務、統計、費率、庫存、計分等有數值輸出的模組 |

**操作五步**

| 步 | 動作 | 產出 |
|---|---|---|
| 1 | 從舊檔抽取計算段落原文 | 貼「檔名＋函式名＋行號＋原文」 |
| 2 | 建立凍結清單，逐條編號 | `FZ-001`、`FZ-002`… |
| 3 | 每條標記：輸入域、輸出域、邊界條件 | 見條目格式 |
| 4 | 新檔對應段落必須逐字包含該原文 | 字元級比對 |
| 5 | 交付時貼「舊段／新段／比對結果」 | 三欄對照 |

**凍結條目格式**

| 欄位 | 說明 | 例 |
|---|---|---|
| 編號 | FZ-{三位數} | FZ-001 |
| 來源 | 檔名＋函式＋行號 | `_summary.js` `_calcBankTotal` L320-335 |
| 原文 | 逐字貼出 | （略） |
| 輸入域 | 參數型別與範圍 | 金額整數 ≥0、年月字串 |
| 邊界 | 已知特殊值 | 初始年月前、跨年、空交易 |
| 新檔位置 | 對應函式＋行號 | `app-data.js` `calcBankTotal` L210-225 |

**通過標準**：所有 FZ 條目在新檔中找到逐字相同段落；任一不符即視為凍結失敗。

**反例**：只寫「公式已保留」；把 `Math.round` 改成 `Math.floor` 卻說「等價」。

### 4.2 差分驗證（Differential Test）

| 項目 | 內容 |
|---|---|
| 目的 | 證明「同輸入 → 同輸出」 |
| 觸發 | 公式凍結完成後、清理舊檔前 |
| 前提 | 舊版仍在（可呼叫舊函式作對照） |

**測試用例格式**

| 欄位 | 說明 |
|---|---|
| 編號 | DT-{三位數} |
| 對應凍結 | FZ-xxx |
| 輸入 | 具體參數值（JSON） |
| 預期輸出 | 由舊版跑出的值（先跑舊版記錄） |
| 新版輸出 | 新函式回傳值 |
| 結果 | 一致／不一致 |
| 覆蓋 | 正常／邊界／異常 |

**執行方式（三選一）**

| 方式 | 適用 | 說明 |
|---|---|---|
| Console 對照 | 函式為純函式 | 舊新各跑一次，貼輸出 |
| 測試頁 | 需 UI 互動 | 臨時 `test.html`，跑完刪除 |
| 手動頁面比對 | 輸出為畫面 | 新舊頁並排截圖比對 |

**通過標準**

| 條件 | 要求 |
|---|---|
| 正常案例 | 100% 一致 |
| 邊界案例 | 100% 一致 |
| 異常案例 | 錯誤行為一致（同拋錯或同回 null） |
| 覆蓋率 | 每個 FZ 至少 1 個 DT |

**反例**：只跑正常案例就宣稱通過；用「新版看起來對」代替數值比對。

### 4.3 驗收清單（Acceptance Checklist）

| 項目 | 內容 |
|---|---|
| 目的 | 人工確認「功能與操作體驗未退化」 |
| 執行者 | 使用者本人（AI 不自評） |
| 阻塞 | 未全勾，不得刪舊檔 |

**清單格式**

| 欄位 | 說明 |
|---|---|
| 編號 | AC-{三位數} |
| 功能 | 一句話描述 |
| 位置 | 頁面＋區塊 |
| 操作 | 具體點擊步驟 |
| 預期 | 可觀察結果（含數值） |
| 對照 | 舊版同操作結果 |
| 勾選 | ☐ |

**分級**

| 級別 | 定義 | 未過處理 |
|---|---|---|
| P0 阻斷 | 登入、資料寫入、金額計算 | 立即回滾 |
| P1 核心 | 主要頁面渲染、CRUD、切換 | 修復後重驗 |
| P2 輔助 | 排序、篩選、空狀態、提示 | 記錄待修 |

**通過標準**：P0 全過、P1 全過、P2 允許 ≤3 項待修（須列單）。

**反例**：AI 自己打勾；只測首頁就說「全站正常」。

### 4.4 重寫期間的回滾保留

> 本節的回滾指**重寫過程中的目錄保留與切換**，與 §三 部署後的緊急回滾互補；§三 處理線上事故，本節處理重寫期間的版本管理。

**目錄約定**

| 路徑 | 內容 | 何時刪 |
|---|---|---|
| `_old/` | 舊版完整鏡像（對應範圍） | 驗收全過後 |
| `index.old.html` | 舊版入口備份 | 驗收全過後 |
| `_new/` | 回滾後的新版保留（供分析） | 事故結案後 |

**觸發條件**

| 情境 | 動作 |
|---|---|
| P0 驗收失敗 | 立即回滾，不修 |
| 差分驗證不一致 | 停止，回報，不繼續 |
| 部署後白屏 | 切 `index.old.html` |
| 中途想停 | 直接切回，無需清理 |

**回滾步驟**

| 步 | 動作 |
|---|---|
| 1 | 將 `_old/` 內容還原至根目錄 |
| 2 | 新版檔案移入 `_new/`（保留供分析） |
| 3 | 清 SW 快取（`sw.js` 版本號回舊） |
| 4 | 驗證舊版可用 |

**通過標準**：任一時點執行回滾，站點恢復至重寫前狀態，資料無損。

**反例**：舊檔先刪再驗收；宣稱「git 可還原」但未實測。

### 4.5 流程閘門

> FZ 完成 → 寫碼 → DT 全過 → AC 全過 → 清舊檔

| 閘門 | 條件 | 未過 |
|---|---|---|
| G1 | FZ 清單完成且凍結 | 不得動工 |
| G2 | DT 全數一致 | 不得進 AC |
| G3 | AC 全勾（P0／P1 全過） | 不得刪 `_old/` |
| G4 | 清舊檔後抽驗首頁 | 若異常，立即回滾 |
