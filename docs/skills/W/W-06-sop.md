## 零、新專案啟動（V2 零到一）

用途：規範從無到有建立全新 Web App 專案的標準順序，防止 AI 在缺乏全局架構時盲目新增檔案，導致專案膨脹。

### 0.1 啟動 5 步法

| 步驟 | 動作 | 產出與要求 |
|---|---|---|
| **1. 架構選擇與環境初始化** | 1. 依照 `W-00 §三` 選擇架構模式。<br>2. 執行 A-00 §4 新專案建立 SOP。<br>3. 若為 Mode B，需建立 Vite、Tailwind 等基礎設定檔。 | `meta.json`、`.github/workflows/notify.yml`。<br>若為 Mode B，需含 Vite 設定檔。確保自動化打包能識別專案。 |
| **2. 確立骨架與設定** | 建立 SPA 目錄結構與路由。**禁止寫任何頁面邏輯**。 | `config/constants.js`（路由表）、`config/state.js`、`engine/router.js`。 |
| **3. 建立通用引擎與 UI** | 實作通用組件（中央廚房）。**禁止綁定任何業務實體**。 | `ui/layout.js`、`ui/table.js`、`ui/form.js`、`ui/modal.js`、`ui/toast.js`。 |
| **4. 跑通最小閉環 (POC)** | 建立一個首頁與一個測試實體。 | 驗證「資料層 ➜ 頁面 ➜ 引擎 ➜ 彈窗」流程。 |
| **5. 業務邏輯填充** | 實作實際業務。**禁止將計算邏輯寫入頁面**。 | 業務邏輯寫在 `domain/` 的純函式中。 |

### 0.2 防膨脹鐵律（MUST）

| # | 鐵律 | 反例（會導致專案失控） |
|---|---|---|
| 1 | **禁止為單一實體建立專屬 UI** | 寫一個 `member-modal.js`、一個 `policy-modal.js`。 |
| 2 | **禁止拆分過細的共用工具** | 把 `escapeHtml`、`formatHKD` 拆成兩個獨立小檔。 |
| 3 | **後端維持單一入口** | 每個實體都建立一個專屬的 API handler 檔案。 |
| 4 | **能改既有檔案就不新增** | 遇到新需求，先思考能否擴充共用元件。 |

## 一、Excel 匯入與動態配置 SOP（防覆寫機制）

**痛點**：每天重新匯入包含舊資料的 Excel 時，如果直接覆蓋資料庫，會導致使用者手動修改的「生產進度」或「交貨日期」被重設。

### 1.1 匯入防覆寫標準流程

1. **資料清洗**：解析 Excel 時，若遇到 A 欄（主鍵/單號）為空，必須 `break` 中斷迴圈（剔除底部總計與備註垃圾資料）。
2. **比對 ID**：使用 `getDocument(collection, id)` 檢查該筆工單是否已存在於資料庫。
3. **分流處理**：
   - **若不存在（新工單）**：使用 `setDocument` 寫入完整資料（含預設狀態）。
   - **若已存在（舊工單）**：使用 `updateDocument`，**僅更新 Excel 來源的欄位**（如金額、客戶名稱、銷售員），**絕對不能覆蓋**狀態 (`status`) 與交期 (`dueDate`)。
4. **動態 Schema 對接**：解析時需比對 `settings.schema`，將自訂欄位寫入 `data` 物件中。

## 三、實作雙清單拖曳排序（Two-List Drag & Drop）

**痛點**：在設定頁面或工單編輯器中，需要讓使用者從「所有可選項目」中挑選，並排定「專屬順序」（如：製程路線、表單欄位順序）。若只提供單一清單，使用者難以直覺操作。

**方案**：採用「左右雙清單」介面。左側為「未選」，右側為「已選」，並透過 HTML5 原生拖曳（Drag & Drop）實現排序。

### 3.1 標準實作流程

| 步 | 動作 | 說明 |
|---|---|---|
| 1 | **建立左右容器** | 使用 CSS Flex 或 Grid 建立兩個區塊。兩側都必須設定 `overflow-y-auto` 與固定高度（如 `h-[40vh]`），避免清單過長撐破彈窗。 |
| 2 | **渲染左側（可選）** | 遍歷「總清單」，過濾掉「已在右側」的項目。點擊時，將其加入右側陣列並重新渲染。 |
| 3 | **渲染右側（已選）** | 遍歷「已選陣列」，渲染時**必須帶入序號**（如 `1. 待印刷`）。每個項目需加上 `draggable="true"` 與 `data-step="${step}"`。 |
| 4 | **綁定左側點擊** | 點擊左側項目 ➜ `currentSteps.push(step)` ➜ 呼叫 `renderLists()`。 |
| 5 | **綁定右側移除** | 點擊右側 X 按鈕 ➜ `currentSteps = currentSteps.filter(s => s !== step)` ➜ 呼叫 `renderLists()`。 |
| 6 | **綁定右側拖曳** | 監聽 `dragstart`、`dragend`、`dragover`。在 `dragend` 時，重新讀取 DOM 順序並更新陣列 ➜ 呼叫 `renderLists()` 以更新序號。 |
| 7 | **儲存** | 按下儲存時，僅將「右側陣列（`currentSteps`）」與其他表單資料寫入資料庫。 |

### 3.2 防呆重點

| # | 防呆點 | 說明 |
|---|---|---|
| 1 | **每次渲染必須重綁事件** | 因為 `innerHTML` 會清空並重建 DOM，所有點擊與拖曳事件必須在 `renderLists()` 的尾端重新綁定。 |
| 2 | **拖曳後必須重算序號** | 拖曳結束後，須重新執行 `renderLists()`，這樣畫面上的 `1, 2, 3...` 才會正確。 |
| 3 | **禁止空清單** | 儲存時檢查右側陣列長度，若為空需顯示錯誤提示（如：製程路線不能為空）。 |
| 4 | **快速套用模板（選配）** | 若右側清單很長，可加入下拉選單，選擇後直接覆蓋右側陣列，免去手動點選。 |

## 五、重寫與重構驗證

用途：證明重寫前後的行為一致。

**核心原則**：先凍結，再重寫；先驗證，再清舊。

| 項 | 編號前綴 | 產出物 | 依賴 |
|---|---|---|---|
| 公式凍結 | FZ | 凍結清單 | 舊檔 |
| 差分驗證 | DT | 測試紀錄 | FZ |
| 驗收清單 | AC | 勾選表 | 新版可跑 |

### 5.1 流程閘門

> FZ 完成 ➜ 寫碼 ➜ DT 全過 ➜ AC 全過 ➜ 清舊檔

| 閘門 | 條件 | 未過 |
|---|---|---|
| G1 | FZ 清單完成且凍結 | 不得動工 |
| G2 | DT 全數一致 | 不得進 AC |
| G3 | AC 全勾（P0／P1 全過） | 不得刪 `_old/` |

## 七、本機 Excel 自動同步 SOP（File System Access API）

**痛點**：手動匯入 Excel 過於繁瑣，希望本地資料夾更新時網頁能自動同步。

### 7.1 標準實作流程
1. **請求權限**：使用 `window.showDirectoryPicker()` 讓使用者選擇本機資料夾。
2. **定時與焦點輪詢**：瀏覽器不支援檔案變更事件，必須使用 `setInterval`（每 2~3 秒）加上 `window.addEventListener('focus')` 主動掃描。
3. **比對修改時間**：取得資料夾內所有 `.xlsx` 的 `lastModified`，比對上次同步時間。
4. **權限防呆**：每次掃描前，必須呼叫 `directoryHandle.queryPermission()`，若未授權則停止輪詢並提示使用者重新綁定。

*(註：此功能僅限電腦版 Chrome / Edge，手機端需在 UI 隱藏此按鈕。)*

## 八、原生瀏覽器推播通知 SOP（Notification API）

**痛點**：希望在工單狀態更新時，即時通知相關的生產員或銷售員。

### 8.1 標準實作流程
1. **請求權限**：登入後呼叫 `Notification.requestPermission()`。
2. **背景監聽**：在 `engine/main.js` 使用 `listenCollection` 監聽工單，比對新舊狀態差異。
3. **權限比對（Route Notification）**：
   - 生產員：檢查工單的「新狀態」是否落在該使用者負責的區域工序內。
   - 銷售員：檢查該工單的「銷售員」是否在該使用者的 `allowedSales` 清單中。
4. **觸發通知**：若比對成功，呼叫 `new Notification('標題', { body: '內容' })`。

*(註：此為純前端推播，網頁必須保持在背景執行，若完全關閉則不會收到通知。)*
