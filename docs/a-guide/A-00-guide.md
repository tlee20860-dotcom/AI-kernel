# R-03 共同語言表

Writer: ai-system-20261020-011#3
用途：定義體系與專案對話中的共同詞彙，確保認知一致。

## 一、詞彙定義

| # | 詞彙 | 定義 |
|---|---|---|
| 1 | 啟動包 (A包) | 新對話時上傳的引導檔，即 `A00.md`。 |
| 2 | 規則包 (R包) | 定義行為與格式的檔案，即 `R00.md`。 |
| 3 | 使用者描述包 (U包) | 定義使用者偏好的檔案，即 `U00.md`。 |
| 4 | 專案包 (S包) | 專案狀態、進度與上下文的檔案，即 `S00` 或 `90-*.md`。 |
| 5 | 對話編號 | 格式 `{專案代碼}-{YYYYMMDD}-{序號3位}`。 |
| 6 | 三段式規則 | 規則寫法：觸發（何時用）→貼出（做什麼）→反例（AI 會怎麼裝懂）。 |
| 7 | 錨點 | A00 末尾的 4 條核心規則，AI 每輪必貼。 |
| 8 | 引導器 | A00 的職責，由 AI 主動要求使用者上傳缺漏的檔案。 |
| 9 | 交付前證據 | 交付檔案前必須貼出的 6 項檢查證據，證明無誤。 |
| 10 | 熱更新 | 對話中途上傳 A00，AI 判定為規則更新，不重置狀態。 |
| 11 | 無字熱更新 | 僅上傳 A00 無文字，AI 預設觸發熱更新並繼續任務。 |
| 12 | 人類中介路由 | 專案需體系修改時輸出「【轉交體系】」，由 Ken 負責轉發。 |
| 13 | 領域技能包 | W / V / D / M 等領域的附屬規則。 |
| 14 | 通用大腦 | 指 A / R / U 三包。 |
| 15 | 專案代碼 | 用於對話編號前綴的英文代碼，如 `webapp`、`ai-system`。 |
| 16 | 專案內序號 | 該專案的第幾個對話，從 `001` 開始。 |
| 17 | 生成時間戳 | 共享包頂部的 `YYYY-MM-DD HH:mm:ss`。 |
| 18 | 領域 | 專案的分類（W / V / D / M）。 |
| 19 | 所屬專案 | 每個檔案、修改方案所屬的專案名稱。 |
| 20 | 交付類型 | 新增、修改、刪除。 |
| 21 | 檔案狀態總表 | 記錄「待交付」與「已交付」的表格。 |
| 22 | 整合交付 | 同一個檔案的多項修改整合成一次交付。 |
| 23 | 先收集後交付 | 討論階段只記錄，確認階段才列清單，交付階段才執行。 |
| 24 | 舊引用更新 | 將舊檔案路徑與編號替換為新架構的過程。 |
| 25 | 體系優先級鐵律 | R00 (鐵律) > A00 (狀態機) > U00 (偏好)。當且僅當邏輯物理互斥時，高階規則才可覆蓋低階，且 AI 必須顯性宣告：「覆蓋聲明：[原因]」。嚴禁 AI 為了免責而假造衝突。 |
| 26 | 意圖解鎖機制 | STATE_WAIT_CONFIRM 下，AI 須主動解析自然語言意圖，對接 A/B/C/D 狀態。若包含多重意圖（如：「好，但有 Bug」），強制執行「負面優先原則」（Bug 優先於肯定）。若包含新問題或新任務，優先解答與處理，並於結尾重申確認選項，嚴禁死板跳針。 |
| 27 | 片段與交付之界線 | 討論期輸出程式碼，僅限「邏輯片段（Snippet）」。判定違規之唯一標準：是否具備「可直接落地的檔案特徵」（包含：F-001標頭、路徑、完整模組、F-005 EOF）。若使用者主動索取完整代碼，AI 須標註「[非正式交付]」後輸出，且嚴禁加上任何檔案標頭。 |
| 28 | 狀態機 | 控制對話行為切換之 7 態架構（STATE_INIT ~ STATE_CHECK），用以隔離「發散討論」與「收斂交付」。詳細觸發條件與轉換鐵律，詳見 A00 §二。<br>（強制令：AI 每次回覆的第一行必須顯性貼出：「[狀態宣告] 當前為 STATE_XXX，執行 YYY」。【反例】：未宣告狀態直接進行討論或交付，視同違規。） |
| 29 | Patch 與完整檔 | 修改量 <30% 使用 Patch（增量修訂）；≥30% 或全新檔使用完整檔交付之模式機制。詳細判定與格式要求，詳見 R-00 §一 R-010。<br>（強制令：交付時必須直接於 F-001 標頭之「🔄 交付類型」欄位標註判定依據，格式為：「{新增/修改/刪除} (模式：{Patch/完整檔}，依據：{事實特徵})」。【反例】：僅寫「修改」，未標註模式與事實依據（如「重寫全檔」、「僅改兩行」）即視為違規。） |
| 30 | 專案三寶 | 新專案必須建立之 meta.json、apply-patch.yml、notify.yml 三大自動化骨架檔案。詳細建立 SOP 與模板，詳見 A00 §八。<br>（強制令：進入新專案建置流程時，必須主動列出這三個檔案並索取確認。【反例】：未列出清單、未索取確認，就直接產出專案內容。） |

## 二、維護規則

|---|---|

| 使用者說「更新詞彙表」 | AI 立刻產出更新後的完整內容 |
| 本表與 R-00 衝突時 | 以 R-00 為準 |
