# R-03 共同語言表

最後更新：ai-system-20261019-010
Version: 1792352000
Writer: ai-system-20261019-010#067
用途：定義體系與專案對話中的共同詞彙，確保認知一致。

---

## 一、詞彙定義

| # | 詞彙 | 定義 |
|---|---|---|
| 1 | 啟動包 (A包) | 新對話時上傳的引導檔，即 `A00.md`。 |
| 2 | 規則包 (R包) | 定義行為與格式的檔案，即 `R00.md`。 |
| 3 | 使用者描述包 (U包) | 定義使用者偏好的檔案，即 `U00.md`。 |
| 4 | 專案包 (S包) | 專案狀態、進度與上下文的檔案，即 `S00` 或 `90-*.md`。 |
| 5 | 對話編號 | 格式 `{專案代碼}-{YYYYMMDD}-{序號3位}`。 |
| 6 | 三段式規則 | 規則寫法：觸發（何時用）→貼出（做什麼）→反例（AI 會怎麼裝懂）。 |
| 7 | 錨點 | A00 末尾的 4 條核心規則，AI 每輪必貼。 |
| 8 | 引導器 | A00 的職責，由 AI 主動要求使用者上傳缺漏的檔案。 |
| 9 | 交付前證據 | 交付檔案前必須貼出的 6 項檢查證據，證明無誤。 |
| 10 | 熱更新 | 對話中途上傳 A00，AI 判定為規則更新，不重置狀態。 |
| 11 | 無字熱更新 | 僅上傳 A00 無文字，AI 預設觸發熱更新並繼續任務。 |
| 12 | 人類中介路由 | 專案需體系修改時輸出「【轉交體系】」，由 Ken 負責轉發。 |
| 13 | 領域技能包 | W / V / D / M 等領域的附屬規則。 |
| 14 | 通用大腦 | 指 A / R / U 三包。 |
| 15 | 專案代碼 | 用於對話編號前綴的英文代碼，如 `webapp`、`ai-system`。 |
| 16 | 專案內序號 | 該專案的第幾個對話，從 `001` 開始。 |
| 17 | 生成時間戳 | 共享包頂部的 `YYYY-MM-DD HH:mm:ss`。 |
| 18 | 領域 | 專案的分類（W / V / D / M）。 |
| 19 | 所屬專案 | 每個檔案、修改方案所屬的專案名稱。 |
| 20 | 交付類型 | 新增、修改、刪除。 |
| 21 | 檔案狀態總表 | 記錄「待交付」與「已交付」的表格。 |
| 22 | 整合交付 | 同一個檔案的多項修改整合成一次交付。 |
| 23 | 先收集後交付 | 討論階段只記錄，確認階段才列清單，交付階段才執行。 |
| 24 | 舊引用更新 | 將舊檔案路徑與編號替換為新架構的過程。 |
