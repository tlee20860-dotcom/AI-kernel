# R-00 規則包

用途：行為鐵律 R、事前提問 S、事後檢查 K、格式規範 F、禁止事項、專案邊界、審查機制。

---

## 零、契約表規範

### 0.1 六欄格式

| 欄位 | 要求 |
|---|---|
| Level | MUST／MUST NOT／SHALL／SHALL NOT |
| Trigger | 何時適用 |
| Requirement | 必須做什麼 |
| Acceptance | 可核對的驗收條件 |
| Counter-example | AI 會假裝做到的具體行為 |
| Verify | 驗證方法 |

### 0.2 禁用詞與可用詞

| 類別 | 詞彙 | 說明 |
|---|---|---|
| 禁用 | 需、確保、注意、盡量 | 規則陳述禁止使用 |
| 可用 | 必須（MUST）、不得（MUST NOT）、應（SHALL）、不應（SHALL NOT）、貼出、列出、執行 | 規則陳述僅可用此組 |

- 中文「應該」屬日常語，不視為規範用語；規範用語一律用「應（SHALL）」。
- `forbidden_words.txt` 管交付內容之偷懶詞；本節管規則陳述之語氣詞。兩者範圍不同，不互相取代。

### 0.3 反例寫法

- 反例必須是「AI 會假裝做到的具體行為」，非抽象描述。

### 0.4 錨點

- 每條規則前加 HTML 錨點，格式：`<a id="r-001"></a>`。

### 0.5 編號穩定

- 規則編號一經發布不改號、不重用；廢除時直接刪除該條、編號跳號，並於 `SYSTEM-EVOLUTION.md` 記錄 `{日期}｜廢除 {檔名} {條號}｜理由｜取代者`。
- 廢除前必須掃描「當下已載入」之檔案引用並改指向；針對未載入之全庫範圍，AI MUST 暫停交付，主動要求 Ken 提供受影響清單或由外部執行 `grep` 腳本確認，嚴禁 AI 憑空捏造未載入檔之掃描結果。

| 6 | 習慣性加 ★ 而無依據 | 每個 ★ 後是否有「依據：」 |
| 7 | 交付後未確認狀態就接續 | 是否在使用者回答四狀態前擅自結束 |

## 七、審查機制

### 7.1 三 AI 模式與 CHK 合成物

| 項目 | 內容 |
|---|---|
| 角色定義 | 詳見 `I-00-identity.md` §三；邊界與輸入對照詳見 `docs/review/ROLE-BOUNDARY.md` |
| 審查項目 | 合成物 `CHK.md`，源檔 `docs/review/REVIEW-FORMAT.md`、`ROLE-BOUNDARY.md`、`CHK-INDEX.md`、`CHK-E.md` 等 |
| 打包 | 由 `setup-structure.yml` 自動合併；缺任一源檔即該步失敗，不產出半套 |
| 上傳時機 | 交付已落實檔案給合規審判者時 |
| 與四檔關係 | 四檔管 AI 行為；`CHK.md` 管已落實檔案的合規核對 |

### 7.2 核對範圍

| 核 | 不核 |
|---|---|
| 檔案內容（規則、條文、邏輯） | 交付外層 Code block（F-003） |
| 檔案內部格式（章節、表格、EOF） | 交付標頭（F-001） |
| 跨檔同步（ID、映射、引用） | 對話層格式（R-014） |
| 是否引起體系 AI 行為混亂 | 一鍵貼上完整性 |

- 交付外層錯誤由 Ken 於貼上時即時判定，不列入 CHK。
- 逐條進退對照詳見 `CHK-INDEX.md` §二、§三。

### 7.3 審查層級（L1~L4）

| 層 | 對比方式 | 追加 |
|---|---|---|
| L1（預設） | 修改前後上下對比 | 無 |
| L2 | L1＋前後對比簡版 | 位置綁內容 |
| L3 | L2＋反向提問 | 貼「應該不存在」的內容 |
| L4 | L3＋改前改後各一組 | 雙向比對 |

### 7.4 層級規則

| 編號 | 規則 |
|---|---|
| LV-01 | 未特別指示，一律 L1 |
| LV-02 | 符合升層條件即升，取最高 |
| LV-03 | 審判者只能建議升層，須附理由 |
| LV-04 | Ken 可在任一時點指定層級 |
| LV-05 | 升層須於該項首行記錄：`CHK-E-xxx｜層級：Lx（理由：…）` |
| LV-06 | 未升層不寫層級，視為 L1 |
| LV-07 | 審判者不得自行升層或降層 |

### 7.5 升層條件

| 條件 | 升到 |
|---|---|
| 跨檔同步（ID、映射、引用） | L2 |
| 新增／刪除整節 | L2 |
| FSM、狀態、角色邊界 | L3 |
| 規則衝突、豁免條款 | L3 |
| Ken 要求重複抽查 | L3 |
| 跨檔＋核心規則同時改 | L4 |
| Ken 明確指定 | 依指定 |

### 7.6 外部 AI 驗證機制（防幻覺）

| 編號 | 規則 |
|---|---|
| RV-01 | 若引入外部 AI（如對抗者或審判者）審查，Ken 可要求其提供「指定段落」的引述或修改建議。 |
| RV-02 | 若進行第二次要求，目標段落不得與第一次完全相同。 |
| RV-03 | 若外部 AI 兩次給出的引述或反饋完全一致，標記為「疑似未真讀（幻覺）」，該次審查作廢。 |
| RV-04 | 外部 AI 不得拒絕提供具體段落的對照要求。 |
